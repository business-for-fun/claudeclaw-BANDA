# Ready2net (r2n) — стенд dev2 и конвейер команды R4G (с 24.10.2026)

**Что это.** Ready2net (r2n) — R4G без n8n: тот же JS узлов, те же webhook-пути и данные, плюс WebSocket-рассылка
изменений экранам. Старая система (n8n на 10.128.0.5: dev.r4g, ready2net.online, sandbox) **заморожена** до переезда
прода: в неё ничего не синкается и не деплоится без явного слова Alex. Команда работает на **dev2**.

**Адреса и доступ (из env процесса, не хардкодить).**
- Стенд: `https://dev2.ready2net.online/` = `R4G_DEV_URL`. Дверь площадки — HTTP basic auth: `R4G_DEV_USER` / `R4G_DEV_PASS`
  (те же, что были для dev.r4g). В Playwright: `browser.newContext({ httpCredentials })`.
- API: `R4G_API_BASE` = `https://dev2.ready2net.online/api/r2n` (старые пути `/webhook/r4g/*` тоже работают).
- Ключ админ-консоли dev2: `R4G_ADMIN_KEY` (ключ dev2-локальный). Свежий браузер БЕЗ ключа перевыпускает ключ
  и выбивает из админки Валеру и Alex — в автотестах класть ключ в `localStorage['r2n_admin_key']` до загрузки страницы.
- Здоровье: `curl -u "$R4G_DEV_USER:$R4G_DEV_PASS" https://dev2.ready2net.online/health` → JSON с `"db":{"ok":true}`.
- WebSocket: `wss://dev2.ready2net.online/ws` (экраны получают «изменилось: темы …» и перечитывают данные; опрос
  остаётся страховкой).

**Где живёт продукт — репозиторий r4g (`projects/r4g`, master), единственный источник.**
| Что | Где |
|---|---|
| Логика узлов | `*.js` в корне репо (как всегда) |
| Графы 13 рабочих workflow | `r2n/workflows/*.json` (`jsCode` узлов пуст — код подставляется из файла) |
| Карта «workflow id :: узел → файл» | `r2n/code-map.json` |
| Имена r2n для журнала/событий | `r2n/workflows.json` |
| Фронтенд | `frontend/` (на dev2 — собранный бандл `vite build --mode r2n`, НЕ Vite HMR) |
| Исполнитель r2n (сервер, хаб, импорт, площадка) | репозиторий `ready2net` — **среда, команда не правит** |

**Конвейер** — `projects/r4g/WORKFLOW.md`, раздел «Ready2net (r2n) — конвейер»: [2] fix → [2r] бэкенд на dev2
(Olaf, `tools/r2n-deploy-dev2.sh`) / [2f] фронтенд на dev2 (Olaf, `tools/r2n-deploy-dev2.sh --frontend`) → [3] Kim
на dev2 → [4] sign-off → [5] прод ЗАМОРОЖЕН. Статус карточки `n8n-sync` теперь означает «ждёт выкладки [2r]/[2f]».

**Пять правил общего с Валерой стенда.**
1. Одноразовые QA-данные (брокеры/трейдеры/раунды `KimQA…`) удалять в той же сессии — их остатки Валера видит как баги.
2. Никаких смоук-раундов и действий по живым данным ради проверки выкладки — проверка встроена в скрипт.
3. Админ-консоль в автотестах — только с ключом (см. выше).
4. Состояние dev2 (том файлов, базу) руками не трогать; копию с прода обновляет супервизор по команде Alex.
5. **Проблема среды — не чинить.** Признаки: сервер отвечает 500 без ошибки workflow в ответе; `/health` не 200;
   не приходят события WebSocket; падает скрипт выкладки; данные расходятся с тем, что только что записали.
   Остановиться, собрать факты (время UTC, запрос, ответ, вывод скрипта) и доложить Начо → Alex. Среду правит супервизор.

**Что исчезло.** n8n-sync [2n], sandbox-sync [5s], проверка «live == repo» (сервер читает код из репо),
«Server unreachable / Timeout» из-за очереди n8n (r2n отвечает за 20–100 мс — если на dev2 что-то висит, это п.5).

> Этот каталог скиллов общий для Gale и Kim — ниже обе роли.

## Твоя часть — Gale (бэкенд)
- Правишь `*.js` как раньше; тест в том же коммите (Rule 8). Код исполняется r2n буквально как в n8n (Node 26, тот же
  набор доступного: `fs`, `$input`, `$json`, `$('Узел')`, `$getWorkflowStaticData`, `this.helpers.httpRequest`;
  нет `process`, `fetch`, `crypto`). Ничего «под r2n» переписывать не нужно.
- Новый Code-узел или новый webhook-путь = правка графа `r2n/workflows/<Workflow>.json` **и** запись в
  `r2n/code-map.json` (`"<workflowId>::<имя узла>": {"file": "<файл>.js"}`). Без записи в карте узел уйдёт на dev2 пустым.
- После коммита выкладку делает Olaf ([2r]); ты не запускаешь скрипт сам (кто пишет код — не выкладывает).
- `backend_changed: yes` в карточке по-прежнему означает «нужна выкладка [2r]».
- Данные на dev2 — копия прода от 23.10; состояние в Postgres (документы staticData) и в томе файлов, как было в n8n.

## Твоя часть — Kim (QA)
- Проверяешь ТОЛЬКО на dev2 (`R4G_DEV_URL`), не на dev.r4g. Регрессия jest как раньше; живые спеки берут API из
  `R4G_API_BASE` и UI из `R4G_DEV_URL` с `httpCredentials` (`R4G_DEV_USER`/`R4G_DEV_PASS`).
- Новый спек: адрес API — `process.env.R4G_API_BASE || 'https://r4g.business-for-fun.com/webhook/r4g'` (как в 171
  переведённом спеке), никаких зашитых адресов.
- Админ-консоль открывать только с `R4G_ADMIN_KEY` в `localStorage['r2n_admin_key']` (addInitScript до goto).
- После каждого сценария удалить то, что создала (Rule 12): стенд общий с Валерой.
- «Timeout», «server did not confirm», «unreachable» на dev2 — не баг нагрузки (её нет), а проблема среды: правило 5,
  в карточку — факты и стоп.
- Прод-смоук (Rule 11) без изменений: ready2net.online остаётся на n8n до переезда.
